# 创建推广短剧元数据设计

日期：2026-08-24
状态：已确认，进入实现
范围：只调整用户端“创建推广”短剧资源列表，并为字段提供管理员维护来源；“推广任务”页面不变。

## 目标

让“创建推广”资源表展示参考页面中的五个字段：分佣范围、上线时间、推广说明、语言、类型，同时保留现有的短剧封面、标题、详情和创建推广任务能力。页面不展示没有后端来源的假数据。

## 数据契约

`provider_drama` 增加两个管理员维护字段：

- `commission_scope`：规范化字符串，使用逗号分隔的范围编码，例如 `ORDER,AD`；读取接口转换为 `commissionScopes` 数组。
- `promotion_description`：用户可见的推广说明文本，可为空。

现有 `description` 继续表示远端短剧简介，`remote_updated_at` 作为用户端“上线时间”的真实时间来源。同步 upsert 只更新远端目录字段，不更新上述两个本地维护字段。

管理员目录接口新增：

`PUT /api/admin/drama/catalog/{id}/promotion-metadata`

请求体：

```json
{
  "commissionScopes": ["ORDER", "AD"],
  "promotionDescription": "1. ...\n2. ..."
}
```

接口复用现有 `/api/admin/drama/**` 的 `ROLE_ADMIN` 权限。范围只接受 `ORDER`、`AD`，说明长度限制为 2000 个字符；空数组和空说明表示清空维护内容。

用户端 `GET /api/user/promotion/dramas` 的列表项新增：

- `description`
- `commissionScopes`
- `promotionDescription`
- `remoteUpdatedAt`

## 页面设计

“创建推广”使用白色表头和白色行背景，行间只保留细水平线，不使用灰色筛选条或灰色表头带。短剧名称列使用封面、红色英文标题、标签、原始标题和简介的紧凑信息单元；长标题和说明使用截断，行高固定在可容纳两行说明的范围内。

列顺序为：

1. 短剧名称
2. 分佣范围（订单/广告标签，空时显示 `-`）
3. 上线时间（`remoteUpdatedAt`，空时显示 `-`）
4. 推广说明（保留换行，空时显示 `-`）
5. 语言
6. 类型
7. 操作

操作列使用左侧竖分隔线，与内容列视觉区分。既有详情抽屉、任务创建弹窗、筛选和接口调用保持不变。

## 实现与测试

后端按 DTO/VO、Service/Impl、Mapper 分层，新增 Flyway V14 和 H2 测试 schema 字段。测试覆盖迁移字段、管理员更新与校验、普通用户读取、同步不覆盖本地元数据及未配置空状态。

前端先为新增字段写列表渲染和空状态测试，再更新 API 类型、表格列和 CSS；运行用户端完整测试、类型检查、lint、格式检查和构建。

## 非目标

- 不修改“推广任务”页面。
- 不新增订单、收益、结算或统计业务。
- 不把截图中的示例文字硬编码为所有短剧的真实内容。
