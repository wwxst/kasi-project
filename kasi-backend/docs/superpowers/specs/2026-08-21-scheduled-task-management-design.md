# 定时任务管理设计

日期：2026-08-21

状态：已实施并验证（2026-08-21）

## 1. 目标

在管理后台“系统配置”下增加轻量的“定时任务”页面，用于管理后端已经注册的固定任务。首个固定任务为 `GoodShort 短剧增量同步`。

任务的名称、编码和执行程序由后端代码定义，管理员不能通过页面新增、删除或修改任务程序。页面只允许维护执行周期、任务说明和启停状态。

首次全量同步继续由管理员在短剧目录页手动发起。只有对应语言已经存在成功的全量同步基线时，定时任务才能自动创建增量同步任务。

## 2. 范围

本次交付包括：

- 后端固定任务注册与数据库调度配置。
- 默认植入 `GoodShort 短剧增量同步`，执行周期为每隔 60 分钟，默认开启。
- 定时扫描到期配置并复用现有短剧目录同步服务创建增量同步任务。
- 定时任务查询、编辑和启停 API。
- 管理后台“系统配置 / 定时任务”菜单、路由、表格和编辑弹窗。
- 后端、前端针对性测试和相关 README 更新。

本次不包括：

- 从页面新增、复制或删除任务。
- 修改任务标题、任务编码或后端执行逻辑。
- Cron 表达式、每天指定时刻、一次性任务或复杂日历规则。
- 运行日志、统计卡片、执行历史、下次执行时间和“立即执行”入口。
- 用定时任务自动替代首次手动全量同步。

## 3. 页面设计

页面位于 `kasi-admin-web` 的“系统配置”一级菜单下：

- 菜单名称：`定时任务`
- 路由：`/system-config/scheduled-tasks`
- 页面结构：沿用现有 `PageContainer`，主体使用单层紧凑表格，不增加说明卡片或嵌套卡片。

表格只包含参考页面中的五列：

| 字段 | 展示规则 |
|---|---|
| 标题 | 固定任务标题，例如 `GoodShort 短剧增量同步` |
| 任务说明 | 展示当前可编辑说明 |
| 执行周期 | 展示为 `每隔60分钟执行一次` |
| 是否开启 | 使用 Switch 展示；超级管理员可直接切换，普通管理员只读 |
| 操作 | 超级管理员显示 `编辑`，普通管理员显示 `-` |

页面不提供搜索、分页、新增、删除、批量操作、统计摘要或执行历史。

点击“编辑”打开紧凑弹窗，只显示以下字段：

1. `执行周期`：固定周期类型“每隔 N 分钟”加数字输入框和“分”单位；本期不提供其他周期类型。
2. 周期辅助文本：根据输入实时显示 `每隔N分钟执行一次`。
3. `任务说明`：多行文本输入。
4. `是否开启`：Switch。

任务标题不出现在可编辑表单中。保存成功后关闭弹窗并刷新表格；校验错误显示在对应字段下，业务错误使用现有全局消息反馈。

## 4. 权限

- `ROLE_ADMIN`：可查询定时任务列表。
- `ROLE_SUPER_ADMIN`：可修改执行周期、任务说明和启停状态。
- 普通管理员在页面中只能查看；后端接口继续作为最终权限边界，普通管理员写请求返回 403。
- 推广用户不能访问任何管理员定时任务接口。

该权限与现有“短剧 API 配置”保持一致：普通管理员可读，超级管理员可写。

## 5. 后端模型

新增 Flyway `V8__scheduled_task_config.sql`，创建 `system_scheduled_task` 表并植入唯一固定任务。表字段如下：

| 字段 | 作用 |
|---|---|
| `id` | 内部自增主键 |
| `task_code` | 固定唯一编码，首个值为 `GOODSHORT_DRAMA_INCREMENTAL_SYNC` |
| `title` | 固定展示标题 |
| `description` | 页面可编辑任务说明 |
| `interval_minutes` | 页面可编辑间隔分钟数 |
| `enabled` | 是否开启 |
| `next_run_at` | 后端内部下一次到期时间，不在本期页面展示 |
| `lease_owner` / `lease_until` | 多实例领取租约，不在 API 中暴露 |
| `created_at` / `updated_at` | 审计时间 |

`task_code` 唯一。首个任务默认值：

- 标题：`GoodShort 短剧增量同步`
- 说明：`每隔60分钟执行一次GoodShort短剧目录增量同步`
- 周期：`60` 分钟
- 状态：开启

执行周期间隔限制为 5 至 1440 分钟。启用任务或修改周期后，将 `next_run_at` 重算为当前时间加新周期；禁用时清空下一次执行时间和未完成租约。

## 6. API

接口位于 `/api/admin/system/scheduled-tasks`：

| 方法 | 路径 | 权限 | 作用 |
|---|---|---|---|
| `GET` | `/api/admin/system/scheduled-tasks` | ADMIN | 查询所有后端固定任务配置 |
| `PUT` | `/api/admin/system/scheduled-tasks/{taskCode}` | SUPER_ADMIN | 修改周期、说明和启停状态 |

更新 DTO 字段：

- `intervalMinutes`：必填，5 至 1440。
- `description`：必填，去除首尾空白后长度不超过 255。
- `enabled`：必填布尔值。

响应 VO 只返回页面需要的字段：`taskCode`、`title`、`description`、`intervalMinutes`、`enabled`。不返回内部 ID、租约、任务处理器类名或其他实现细节。

## 7. 调度流程

新增独立的固定任务调度器，每分钟扫描一次到期且已开启的配置。配置扫描频率与业务执行周期分离；页面设置的 60 分钟表示任务入队周期，不是调度线程休眠时间。

`GOODSHORT_DRAMA_INCREMENTAL_SYNC` 到期后的处理流程：

1. 使用数据库条件更新和租约领取到期配置，避免多个应用实例重复处理。
2. 读取已启用且具备目录同步能力的 GoodShort 接入连接。
3. 按已配置语言检查成功的全量同步基线。
4. 没有成功全量基线的语言直接跳过，不自动升级或创建全量任务。
5. 已有 `REQUESTED` 或 `RUNNING` 同步任务的语言直接跳过，不重复排队。
6. 对满足条件的语言复用现有目录同步服务创建 `INCREMENTAL` 任务。
7. 无论本轮是成功入队还是因基线/运行中任务而跳过，都将下一次到期时间推进一个完整周期，避免高频空转。
8. 领取后发生未处理异常时记录日志并释放或等待短租约过期；不得修改现有成功同步检查点。

现有 `DramaCatalogScheduler` 继续每 5 分钟领取并执行已经排队的目录同步任务。本次新增调度器只负责按配置创建增量任务，不直接调用 GoodShort，也不取代现有同步执行器。

## 8. 前端模块

`kasi-admin-web` 增加：

- `src/features/scheduled-task/`：类型、查询 API 和更新 API。
- `src/pages/system/ScheduledTaskPage.tsx`：表格、开关和编辑弹窗。
- 页面专属 CSS：只处理紧凑列宽、周期组合输入和响应式收缩。
- `AppRouter.tsx`：懒加载 `/system-config/scheduled-tasks`。
- `AdminLayout.tsx`：在“系统配置”下增加“定时任务”菜单项，使用现有 Lucide 任务/时钟类图标。

不引入新的全局状态或组件库。请求继续使用现有 Axios 包装和统一响应解包。

## 9. 测试与验收

后端测试覆盖：

- V8 迁移表结构、唯一任务和默认值。
- 普通管理员查询成功、写入返回 403、超级管理员更新成功。
- 周期和说明的 Jakarta Validation。
- 启用、禁用和修改周期时 `next_run_at` 的计算。
- 无全量基线不入队，有全量基线创建增量任务。
- 已有活动任务不重复入队。
- 多实例租约只允许一个调度器领取同一到期任务。
- 调度开关和调度器委托行为。

前端测试覆盖：

- 菜单和路由可访问。
- 表格严格展示五列和后端返回值。
- 编辑弹窗只包含执行周期、任务说明和是否开启。
- 周期辅助文本随数字变化。
- 超级管理员可编辑和切换状态，普通管理员只读。
- 保存成功刷新数据，校验和接口错误正确反馈。

完成后分别运行后端 Java 25 聚焦测试、完整测试、编译和 `git diff --check`，以及前端 `pnpm test`、`pnpm typecheck`、`pnpm lint`、`pnpm format:check`、`pnpm build`。
