# 未支付订单落库设计

## 当前目标

甲方 GoodShort 订单接口返回 `payStatus=0`（未支付）时，本地订单也要保存。当前本地订单状态只有 `PAID` 和 `REFUNDED`，需要增加 `UNPAID`，同时保持用户端不暴露完整订单金额或内部佣金字段。

## 数据流与状态

- GoodShort 适配器继续按甲方字段读取 `orderId`、`userId`、`payMoney`、`payTime`、`payStatus`、`customParams`、`bookId`、`searchCode`、`channelCode`、`pid`、`utime`。
- `payStatus=0` 映射为本地 `UNPAID`；`1` 映射为 `PAID`；`3` 映射为 `REFUNDED`。
- 其他未知值仍不写入本地订单，避免把未定义状态伪装成有效订单。
- 数据库状态约束改为允许 `UNPAID`、`PAID`、`REFUNDED`。

## 查询与展示

- 管理端订单查询和导出允许查看三种本地订单状态，并继续保留完整金额和佣金核对字段。
- 用户端只查询本人已归因订单，允许展示三种支付状态。
- 用户端 JSON/CSV 仍只包含甲方订单号、币种、支付状态、支付时间、跟踪号和本人收益。
- `UNPAID` 订单不计算佣金；用户端收益显示为 `0`（或后端返回的空收益按现有前端格式显示为 `-`），不返回完整订单金额。
- 月度汇总的已支付订单数只统计 `PAID`，未支付订单不计入已支付数量和收益。

## 实施与验证

- 先新增覆盖未支付映射、同步落库、数据库状态约束和用户端展示边界的失败测试。
- 修改状态枚举、同步过滤、查询默认状态条件、月度汇总 SQL、用户端类型和状态文案。
- 运行订单聚焦测试、后端完整 `verify`、用户端 `pnpm check` 及 `git diff --check`。

## 非目标

- 不新增退款时间、结算状态、佣金状态到用户端。
- 不改变甲方原始字段契约，不为未知 `payStatus` 创建本地订单。
