## 执行原则

- 一次只实现、测试和验收一个模块。
- 当前模块没有通过完整回归测试和用户验收前，不开始下一模块。
- 每个模块使用独立实施计划和独立提交；除用户明确批准的共享数据库基础外，不能把后续模块的表、接口或抽象提前混入。
- README 和 AGENTS.md 只记录已经实现并验证的能力；未完成内容留在设计规格和路线图中。
- 所有模块继续遵循当前 Controller、Service 接口与 `impl` 实现、Mapper、Entity、DTO、VO 分层。

## 模块顺序

### 模块 1：短剧平台接入账号与 GoodShort 通信基础

交付：

- 短剧平台和单平台单接入账号的数据结构。
- GoodShort `pid + key` 的安全保存和脱敏展示。
- GoodShort 固定向量签名实现。
- 管理员查看、配置和测试 GoodShort 接入账号的后端接口。
- 平台能力声明基础；GoodShort 明确不支持锚点。

不包含：短剧同步、媒体账号、报备、素材、推广链接、订单、佣金和转化数据。

### 模块 2：GoodShort 短剧目录

依赖模块 1。交付全量/增量同步、同步检查点、后台列表、上下架和同步状态。此模块只服务管理员，不开放推广用户选剧页面。

### 模块 3：媒体账号与 GoodShort 报备

依赖模块 1。交付推广用户媒体账号绑定、全局唯一归属、不可转让、资料修正、停用、GoodShort 报备和审核状态轮询；业务状态只使用“审核中、已加白、已失败”。

### 模块 4：平台短剧分佣规则

依赖模块 2。交付按平台短剧和生效时间配置五项费率、时间段不重叠校验、BigDecimal 计算器及“无有效规则不可推广”状态。此模块不接订单。

### 模块 5：素材与推广链接

依赖模块 2、3、4。交付短剧详情、免费内容播放、单集/批量下载任务，以及同一账号和短剧生成多条推广链接。GoodShort 使用本地 `tracking_no` 作为 `customParams`。

### 模块 6：订单、预计佣金与导出

依赖模块 4、5。交付每 5 分钟轮询、历史复核、订单幂等归因、未支付/已支付/已退款状态、费率快照、预计佣金和管理员 Excel 导出。不建设钱包、提现和已结算状态。

### 模块 7：每日转化数据

依赖模块 5。交付按推广链接和自然日同步点击、注册、充值、订单等指标，以及推广用户本人数据和管理员全量数据查询。
