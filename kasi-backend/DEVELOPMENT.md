# Kasi Backend 开发与变更规范

本文件是仓库级开发流程的详细说明。`AGENTS.md` 是执行时的强制摘要；本文件说明如何把问题拆解、修复、验证并沉淀。适用范围为本仓库全部 Java、SQL、配置、测试和文档变更。

## 1. 基本原则

- 每次修错先梳理问题和根因，再决定改动。
- 每个阶段只解决一个可验证的问题。
- 优先建立清晰模块边界，再增加功能。
- 优先最小改动；未发布 API 允许破坏性重构，不保留无意义兼容层。
- 不因“以后可能需要”预先实现复杂系统。
- 重要架构决策必须进入仓库文档，不能只存在于聊天或口头约定。
- 当前实现、已批准方案和未来建议必须分开记录。

## 2. 变更分级与闸门

| 级别 | 范围 | 必须动作 | 是否需要先汇报 |
| --- | --- | --- | --- |
| L0 | 文档、注释、格式，不改变运行行为 | 说明影响范围；检查链接和 `git diff --check` | 否 |
| L1 | 单模块内部实现或缺陷修复，不改变外部契约 | 根因记录、针对性测试、编译/测试验证、文档同步 | 通常否 |
| L2 | 跨模块调用、API/DTO/错误码、数据库 schema、权限、安全、配置或异步任务契约 | 先写设计/ADR；列出兼容性、迁移、回滚和验证；按阶段实施 | 是 |
| L3 | 破坏性重构、公开契约替换、数据迁移或运行模型改变 | 明确影响面、停机/重建窗口、迁移脚本或重建步骤、回滚方案和验收标准 | 必须 |

变更过程中如果范围从 L1 升为 L2/L3，立即暂停实现并重新确认，不通过继续堆叠改动来规避闸门。

## 3. 缺陷修复流程

### 3.1 建立问题单元

在任务描述、设计文档或提交说明中写清：

1. 现象：用户或测试实际看到什么。
2. 影响：影响哪些接口、数据、角色、环境和严重程度。
3. 复现：最短可重复命令、请求、输入或测试名称。
4. 证据：日志、堆栈、SQL、断言、状态快照或代码路径。
5. 根因假设：按可能性排序，并写出如何证伪。
6. 非目标：本阶段明确不解决的相邻问题。

### 3.2 拆分阶段

每个阶段使用“一个问题 + 一个完成标准 + 一组验证”的格式。依赖关系必须显式写出；不要在一次提交中混入无关重构、顺手清理或未来功能。

### 3.3 选择修复

先选择影响面最小且能消除根因的方案。只有以下情况才扩大范围：

- 根因位于共享边界，局部修补会继续制造不一致；
- 数据、权限或安全契约无法通过局部改动保证；
- 当前结构阻止可重复测试或明确模块职责。

扩大范围时必须升级为 L2/L3，并补充设计、迁移和回滚说明。

### 3.4 验证与完成

至少完成：

- 正常路径、失败路径和边界条件的针对性测试；
- 受影响模块的编译或完整测试；
- 涉及 SQL 的初始化执行、schema/fixture 检查；
- 涉及权限、会话、密钥、个人信息的安全回归；
- `git diff --check`、工作区状态和明确的文件清单复核。

没有显示零失败、零错误的最新输出时，只能报告“验证未完成”或“存在阻塞”，不能报告“已修复”。

## 4. 功能开发流程

1. 明确模块边界、输入输出、数据所有权和不在本阶段实现的内容。
2. 对 L2/L3 变更先写设计或 ADR，并取得确认。
3. 先定义可观察的接口/服务行为和失败契约，再编写实现。
4. 为 Controller、Service、Mapper、数据库结构、安全规则或调度器增加针对性测试。
5. 按阶段实现，每完成一个阶段就验证并更新状态，不把多个独立阶段一次性标成完成。
6. 更新当前行为文档、缺口清单和架构决策状态；规划内容不得混入“已实现”章节。

## 5. 需要暂停并汇报的情况

- 发现根因需要改变公开 API、数据库字段语义、权限模型、会话模型或外部平台契约；
- 数据库无法按当前约定删除重建，或需要保留数据、迁移数据或安排停机窗口；
- 测试环境、Redis、MySQL、Java 版本或外部平台状态导致证据不足；
- 现有未提交改动与目标文件冲突，无法在不覆盖用户工作的情况下继续；
- 发现第二个独立问题且修复它会扩大本阶段范围。

汇报内容必须包含：已确认事实、阻塞原因、影响范围、可选方案和推荐方案。不得用猜测替代确认。

## 6. 完成检查表

- [ ] 问题现象、根因证据和非目标已记录。
- [ ] 本阶段只有一个清晰问题，变更级别已判断。
- [ ] L2/L3 已完成设计/ADR 和确认。
- [ ] 代码、SQL、配置和测试只包含本阶段必需改动。
- [ ] 针对性验证和受影响范围验证均有最新结果。
- [ ] 当前行为、规划边界和缺口清单已同步。
- [ ] `git diff --check` 通过，未暂存无关文件，未覆盖用户改动。
