# 用户工作区错误处理设计

## 目标

移除账号报白页直接渲染的 Axios 英文错误。未认证访问和失效会话按认证边界回到登录页，普通接口失败使用 TDesign Starter 的 `MessagePlugin.error` 提示。

## 当前问题与根因

- `MediaAccountsPage` 在查询失败时直接渲染 `query.error.message`，因此 HTTP 401 显示为 `Request failed with status code 401`。
- `AppRouter` 没有读取认证状态，未登录用户仍能进入工作区并发起受保护请求。
- 共享 Axios 响应拦截器已经只在 HTTP 401 时清理会话；这一边界保持不变。

## 设计

- 新增工作区路由保护组件。存在 access token 时渲染 `AppShell`，否则使用 React Router `Navigate` 返回 `/login`。
- token 在受保护请求中失效时，Axios 拦截器清除 Zustand 登录态；路由保护随状态更新并跳转登录页。
- 账号报白页不再渲染错误文本。非 401 查询失败时调用 TDesign `MessagePlugin.error('账号报白加载失败，请稍后重试')`。
- 401 不触发页面级提示，避免清会话和页面错误提示重复；登录页本身就是用户需要采取的动作。
- 查询失败时保留筛选表单和空表格结构，不用错误文本替换整个表格区域；无数据时显示“暂无报白账号”。

## 验证

- 未登录直接访问 `/workspace/media-accounts` 时跳转 `/login`，且不调用账号报白接口。
- 已登录用户仍能进入账号报白筛选列表页。
- 普通查询失败只显示 Starter 消息提示，不显示原始错误字符串。
- HTTP 401 由共享拦截器清会话后触发路由跳转，不产生页面级重复提示。
- 运行完整测试、类型检查、lint、格式检查和生产构建。

## 非目标

- 不改变后端认证或账号报白 API。
- 不把 403、503、网络错误或业务错误当成 401 清理会话。
- 不在本次修改中建立全站错误文案系统。
