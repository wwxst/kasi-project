# 管理员与用户管理查询表格页设计

## 目标与来源

管理员管理和推广用户管理直接移植 Ant Design Pro `table-list` 页面结构，使用官方 `@ant-design/pro-components` 的 `PageContainer`、`ProTable`，以及 Ant Design 的 `Drawer`。参考仓库为 `ant-design/ant-design-pro`，源码路径为 `src/pages/table-list`，参考提交为 `bb40867ae3ef943e06e48da6911ccc5900e638a1`，许可为 MIT。

当前项目继续使用 React Router、Axios 和现有认证状态，不引入 Umi。官方页面的批量选择和批量工具条依赖后端批量接口，当前系统没有相应接口，因此不移植。

## 页面与权限

- `/admin-management`：仅超级管理员可见、可访问。
- `/user-management`：超级管理员和普通管理员均可见、可访问。
- 未授权访问通过前端路由回到 `/dashboard`，后端权限仍是最终边界。

## 页面结构

两个页面统一使用官方 Table List 结构：PageContainer 页面标题和说明、ProTable 查询表单、表格标题、新建按钮、刷新/密度/列设置/全屏工具、数据表格和分页器。查询表单只显示关键词，列表请求映射为后端支持的 `keyword`、`page` 和 `size`。

管理员表格列严格为：姓名、手机号、邮箱、角色、登录时间、状态、操作。操作列为“详情｜删除”，唯一超级管理员的删除按钮禁用。管理员状态只读显示为标签，不提供启用/禁用入口。

用户表格列严格为：用户 ID、昵称、手机号、邮箱、注册来源、状态、操作。操作列为“详情｜更多”，“更多”菜单包含启用/禁用和删除。状态列只读显示为标签，不使用开关。

## 详情与编辑

“详情”先调用对应详情接口，再从页面右侧打开宽抽屉。抽屉内按“基本信息”和“账号资料”分组为白色信息块，标题左侧使用蓝色竖线，字段使用两列布局，空值统一显示 `-`；移动端改为单列。基本信息标题右侧提供“编辑”，点击后在详情抽屉之上打开较窄的右侧编辑抽屉，底部固定提供取消和确认按钮。

编辑表单只包含后端已有且允许更新的字段，不移植参考页面中的会员等级、收货信息、资金、积分或密码字段。管理员编辑使用 `PUT /api/admin/management/{id}`，唯一超级管理员不显示编辑入口；推广用户编辑使用 `PUT /api/user/management/{id}`。表格操作列仍不展示编辑按钮。

## 其他写操作

新建继续使用表单弹窗。删除必须经过确认对话框，成功后刷新当前表格。用户启用/禁用通过“更多”菜单调用状态接口，成功后刷新表格。重置密码 API 契约保留在 API 层，但当前页面没有入口。

| 资源     | 列表                        | 详情                             | 新增                         | 编辑                             | 状态                                     | 删除                                |
| -------- | --------------------------- | -------------------------------- | ---------------------------- | -------------------------------- | ---------------------------------------- | ----------------------------------- |
| 管理员   | `GET /api/admin/management` | `GET /api/admin/management/{id}` | `POST /api/admin/management` | `PUT /api/admin/management/{id}` | 当前页面不提供入口                       | `DELETE /api/admin/management/{id}` |
| 推广用户 | `GET /api/user/management`  | `GET /api/user/management/{id}`  | `POST /api/user/management`  | `PUT /api/user/management/{id}`  | `PATCH /api/user/management/{id}/status` | `DELETE /api/user/management/{id}`  |

## 验收

- 用户管理列表与详情中的“用户ID”统一展示后端 `userNo`（数据库字段 `user_no`）；内部主键 `id` 只用于详情、编辑、状态和删除接口路由，不展示给管理员。
- 管理员页只显示指定七列，操作为详情和删除；分组详情抽屉读取真实接口，普通管理员可从详情进入编辑抽屉，唯一超级管理员不能编辑或删除。
- 用户页只显示指定七列，操作为详情和更多，更多菜单包含启用/禁用和删除。
- 两个页面不存在状态开关、表格编辑入口和重置密码入口；编辑只从详情抽屉进入。
- 查询、重置、新建、详情、编辑、状态更新、删除和刷新行为有自动化测试。
- 运行 `pnpm test`、`pnpm typecheck`、`pnpm lint`、`pnpm format:check`、`pnpm build`，并在浏览器中验收两个路由。
