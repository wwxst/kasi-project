# 推广短剧库与链接工作流设计

## 目标

将推广链接页调整为接近参考推广平台的工作流：推广用户先在短剧库中筛选已上架短剧，再查看短剧详情和剧集信息，选择本人已报白的媒体账号，填写推广名称并生成可追踪的推广链接，最后在页面下方查看本人历史链接。

## 范围

本阶段只改 `kasi-user-web` 前端，复用现有后端接口：

- `GET /api/user/promotion/dramas`：已上架短剧分页查询。
- `GET /api/user/promotion/media-accounts`：本人媒体账号及报备状态。
- `GET /api/user/promotion/links`：本人推广链接记录。
- `POST /api/user/promotion/links`：按短剧、媒体账号和链接类型生成推广链接。

页面支持短剧名称、平台、语言、短剧类型和本地状态筛选；筛选结果以表格/列表展示封面、标题、平台、语言、类型和操作。点击短剧可打开详情抽屉，展示短剧元数据和可用剧集；点击“创建推广任务”打开生成表单，填写任务名称、选择已报白媒体账号和链接类型后调用现有生成接口。生成成功后展示分享链接、推广口令、追踪号和状态，并允许复制分享链接。

本阶段不实现排行榜、订单收益、视频下载、TikTok 锚点、第三方推广任务异步状态和新的数据库表。后端未提供对应接口时，页面不显示伪造数据或不可用操作。

## 交互与数据流

1. 页面加载短剧第一页、媒体账号列表和本人链接记录。
2. 用户提交筛选条件时重新请求短剧列表；分页只影响短剧列表，不改变已加载的媒体账号。
3. 用户打开短剧详情时使用短剧对象中的已有字段；没有剧集详情接口时展示可用元数据和明确的“剧集信息由后端同步后提供”空状态，不发起猜测接口。
4. 生成表单只列出状态启用且针对当前平台报备状态为 `APPROVED` 的媒体账号。
5. 生成请求继续使用前端随机 `requestKey`，由后端保证幂等；成功后刷新链接记录并将最新结果置于结果区。
6. 列表、详情、生成和复制操作分别提供加载、空数据和错误状态；接口错误使用现有 `ApiError` 展示，不暴露凭据或内部异常。

## 组件边界

- `PromotionLinkPage`：页面编排、筛选状态、详情抽屉和生成结果。
- `promotionLinkApi`：保留现有链接接口，补充短剧筛选参数类型。
- `dramaTypes`：补充列表筛选字段和详情展示所需的可选元数据。
- `promotion-link.css`：沿用当前 TDesign 风格，增加筛选工具栏、短剧列表、详情抽屉和移动端布局。

不引入新的状态管理库；短剧、媒体账号和链接记录继续使用 TanStack Query。筛选条件作为页面本地状态，切换短剧时清空不匹配的媒体账号选择。

## 验证

- 页面测试覆盖初次加载、筛选请求、详情抽屉、无可用媒体账号、成功生成、失败提示、复制链接和历史记录。
- 运行 `pnpm test`、`pnpm typecheck`、`pnpm lint`、`pnpm format:check` 和 `pnpm build`。
- 不修改后端合同；如果实际后端响应缺少页面所需字段，页面保留空状态并在后续单独提出接口变更。
