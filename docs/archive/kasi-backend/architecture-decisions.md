# 架构决策记录规范

本文件定义本仓库如何记录重要架构决策。重要决策不能只存在于聊天、代码注释或某次提交信息中。

## 1. 何时必须记录

满足任一条件就必须新增或更新记录：

- 改变模块边界、依赖方向、事务边界或数据所有权；
- 改变 API、DTO、错误码、权限、会话、配置或数据库契约；
- 引入或移除外部平台、异步任务、缓存、一致性或并发模型；
- 采用破坏性重构、迁移/重建策略或影响运行与发布流程的技术方案；
- 明确拒绝一个会影响后续实现的备选方案。

单纯修复单模块内部实现且不改变上述契约时，可在模块文档和提交说明中记录，不必新增 ADR。

## 2. 记录位置与状态

本文件是索引和规则入口；详细记录可直接追加在本文件，或放在 `docs/adr/ADR-XXXX-<slug>.md` 并在此处建立索引。状态只能使用：

- `提议`：正在讨论，不能作为当前实现依据；
- `已批准`：方案已确认，但尚未全部交付；
- `已实施`：代码、迁移、测试和文档已完成并有验证证据；
- `已废弃`：被新决策替代，必须链接替代记录。

README 和 AGENTS 只能引用 `已实施` 的当前行为；`提议`、`已批准` 和 `已废弃` 必须明确标注状态。

## 3. 必填记录格式

```markdown
# ADR-XXXX: 标题

- 日期：YYYY-MM-DD
- 状态：提议 | 已批准 | 已实施 | 已废弃
- 范围：模块、接口、数据表或运行环境
- 关联：任务、Issue、设计文档、替代或被替代 ADR

## 背景与问题
描述触发决策的事实、约束和根因证据。

## 决策
写出唯一明确的采用方案、边界和不做的事情。

## 备选方案
列出至少一个被拒绝方案及拒绝理由；没有实际备选时说明原因。

## 影响
说明对 API、数据、权限、性能、运维、测试和开发体验的正负影响。

## 迁移与回滚
说明开发库重建、Flyway、数据迁移、发布顺序和失败回滚方式；不需要时写明“不需要”。

## 验证证据
列出测试命令、关键结果、运行环境和文档同步位置。
```

## 4. 当前决策索引

已有专项设计文档仍然有效，但在状态更新前应按本规范补齐“状态、影响、迁移/回滚、验证证据”。后续新决策从 `ADR-0001` 开始连续编号，不复用编号，不删除历史记录。
