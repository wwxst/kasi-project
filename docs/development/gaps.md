# 当前缺口

## 快速上线前必须确认

- GoodShort 订单人工同步、重复数据幂等、失败重试和账单导出需要以真实甲方样例做验收。
- 管理端和用户端的订单、收益字段必须与后端现有 API/VO 一致，不能把统计占位值描述为真实收益。
- 生产环境必须配置真实验证码发送器、MySQL、Redis、JWT 密钥和平台凭据。
- 必须补齐部署、回滚、数据库备份和首个生产账号改密流程。

## 后续能力

- 钱包、提现、用户月度账单确认和自动结算。
- 订单异常审核、人工修正审计和更完整的对账流水。
- CapCut 人工导入及 CPA 规则；CPM 和通用项目结算模型。
- 更细粒度的权限模型和跨端契约生成。

## 明确不做

- 不在本阶段接入 CapCut 甲方 API。
- 不重新计算甲方已完成的 T+14。
- 不按甲方结算时间替代发稿日期归属月份。
- 不把上游结算价展示给普通推广用户。
