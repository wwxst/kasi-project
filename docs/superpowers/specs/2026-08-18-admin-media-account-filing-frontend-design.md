# 管理员端媒体账号报备页面设计

## 目标

为管理后台增加媒体账号报备管理页面。管理员可以查看推广用户绑定的媒体账号、查看报备详情、编辑账号资料，并对失败的报备任务进行重试。

本阶段不提供管理员新增或删除媒体账号。媒体账号仍由推广用户端创建，后端保留账号归属和唯一性约束。

## 页面结构

- 路由：`/promotion/media-accounts`
- 菜单：推广管理下的“媒体账号报备”
- 页面容器：复用现有 `PageContainer`
- 列表：复用现有 `ProTable`
- 详情：右侧 `Drawer`
- 编辑：从详情抽屉进入编辑状态，保存后刷新详情和列表

列表字段：

| 字段 | 说明 |
| --- | --- |
| 用户编号 | 推广用户 `user_no` |
| 用户昵称 | 推广用户昵称 |
| 媒体平台 | TikTok、Facebook、YouTube、Instagram |
| 账号 ID | 平台账号唯一标识 |
| 账号名称 | 平台账号名称 |
| 账号状态 | 启用或禁用 |
| 报备状态 | 审核中、已加白、已失败 |
| 更新时间 | 媒体账号最近更新时间 |
| 操作 | 详情 |

筛选条件：用户编号、媒体平台、账号状态、短剧平台、报备状态。列表支持分页、重置和刷新。

## 详情与编辑

详情抽屉分为三块：

1. 推广用户信息：用户编号、昵称、姓名。
2. 媒体账号资料：媒体平台、账号 ID、账号名称、主页链接、账号状态、创建时间、更新时间。
3. 平台报备：短剧平台、报备状态、外部报备编号、最近操作时间、失败原因和下次处理时间。

详情顶部提供“编辑”按钮。编辑表单允许修改：账号名称、主页链接、账号状态；媒体平台和账号 ID 默认只读，避免改变已建立的账号身份。若业务后续确认需要纠正账号 ID，必须通过重新绑定流程处理，不在管理员编辑中直接覆盖。

报备状态为“已失败”时，显示“重试报备”按钮；其他状态不显示重试按钮。重试成功只代表任务重新进入审核流程，页面状态刷新为“审核中”。

## 后端接口

现有接口继续使用：

- `GET /api/admin/promotion/media-accounts`
- `GET /api/admin/promotion/media-accounts/{id}`
- `POST /api/admin/promotion/media-accounts/{id}/filings/{providerId}/retry`

新增管理员编辑接口：

- `PUT /api/admin/promotion/media-accounts/{id}`

请求字段：`accountName`、`profileUrl`、`status`。

后端必须重新校验记录存在、账号状态值、主页链接格式，并在资料变更后按现有版本隔离规则重新生成对应报备任务。接口响应不得暴露平台密钥、内部租约字段或数据库内部关联字段。

## 状态和错误处理

- `PENDING` 显示“审核中”。
- `APPROVED` 显示“已加白”。
- `FAILED` 显示“已失败”，同时展示失败原因。
- 列表、详情、编辑、重试请求失败时使用统一错误提示，不清空已加载的详情数据。
- 保存成功后关闭编辑状态，重新请求详情并刷新列表；重试成功后同样刷新报备状态。
- 无权限时沿用后端 403/业务错误提示；管理员页面不向前端暴露敏感配置。

## 测试范围

- API 类型和请求封装测试：列表、详情、编辑、重试路径。
- 页面测试：筛选、分页、详情抽屉、编辑保存、失败重试和错误提示。
- 后端新增编辑接口的权限、校验、唯一性和报备任务版本隔离测试。
- 浏览器验证桌面端和移动端抽屉布局。

## 不在本阶段范围

管理员新增/删除媒体账号、推广用户端页面、短剧目录、推广链接、订单、佣金、提现、导出和转化分析。
