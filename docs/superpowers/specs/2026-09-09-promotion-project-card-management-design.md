# 推广项目 CRUD 与用户端卡片设计

日期：2026-09-09

状态：已实施（后端全量 Gate 仍有两个既有 GoodShort 定时任务断言失败）

## 1. 背景

用户工作台当前将推广项目卡片写死在页面代码中。后台需要提供项目的新增、查询、修改和删除能力，用户端根据后台维护的启用项目动态展示卡片。

每个项目只维护项目名称、封面图片、项目文档 URL、启用状态和显示顺序。封面图片由管理员上传到后端，项目文档通过外部链接打开。

## 2. 目标

- 后台可以新增、查询、修改和物理删除项目。
- 后台可以上传和替换项目封面图片。
- 后台可以启用、停用项目并调整显示顺序。
- 用户端从接口读取启用项目，不再把项目列表写死在页面组件中。
- 用户端下一次加载或重新请求项目列表时，新增且启用的项目显示为新卡片，修改后卡片同步更新，停用或删除后卡片消失。
- 用户点击卡片中的“项目文档”后，在新标签页打开后台配置的项目文档 URL。

## 3. 非目标

- 不维护项目类型、项目唯一业务编码或其他扩展属性。
- 不实现报白入口、报白配置或报白流程。
- 不实现 CapCut 账号、订单归属或其他项目专属业务。
- 不实现项目发布、下线、归档或软删除流程。
- 不实现项目文档编辑器、项目文档文件上传或后端代理访问。
- 不通过 WebSocket 等机制向已打开的用户页面实时推送项目变化。
- 不建立项目与推广链接、媒体账号、订单或其他业务数据的关联。

## 4. 数据库设计

新增 `promotion_project` 表：

```text
promotion_project
- id                       自增主键
- name                     项目名称
- cover_image_url          后端保存的封面访问路径
- project_document_url     项目文档 HTTPS URL
- status                   ENABLED / DISABLED
- sort_order               显示顺序
- created_at
- updated_at
```

数据约束：

- `name` 去除首尾空白后不能为空。
- `cover_image_url` 不能为空，只保存后端上传成功后生成的访问路径。
- `project_document_url` 不能为空且只允许 `https://` URL。
- `status` 只允许 `ENABLED` 或 `DISABLED`，新增时默认为 `ENABLED`。
- `sort_order` 为大于或等于 `0` 的整数，数值越小越靠前。
- 允许多个项目使用相同的 `sort_order`；同序时按 `id ASC` 稳定排序。
- 删除项目时直接物理删除数据库记录，不保留删除标记。
- 表不建立与其他业务表的物理外键或逻辑关联。

生产环境新增表只能通过新的 Flyway 迁移，开发重建脚本必须同步更新。

## 5. 管理端接口

```http
GET    /api/admin/promotion/projects?page=1&size=20
GET    /api/admin/promotion/projects/{id}
POST   /api/admin/promotion/projects
PUT    /api/admin/promotion/projects/{id}
DELETE /api/admin/promotion/projects/{id}
```

已登录管理员可以使用以上接口。列表按 `sort_order ASC, id ASC` 排序，并返回分页结果。

新增和修改使用 `multipart/form-data`：

| 字段 | 新增 | 修改 | 说明 |
| --- | --- | --- | --- |
| `name` | 必填 | 必填 | 项目名称 |
| `coverFile` | 必填 | 可选 | 不上传新文件时保留原封面 |
| `projectDocumentUrl` | 必填 | 必填 | 项目文档 HTTPS URL |
| `status` | 可选 | 必填 | 新增未传时默认为 `ENABLED` |
| `sortOrder` | 必填 | 必填 | 大于或等于 `0` |

接口行为：

- 新增成功后保存项目记录并返回完整项目数据。
- 修改时若上传新封面，则保存新文件并替换 `cover_image_url`；未上传则保留原封面。
- 修改和删除不存在的项目时返回统一的资源不存在业务错误。
- 删除成功后物理删除项目记录。
- 名称、文档 URL、状态和排序参数不合法时返回参数校验错误。

## 6. 封面图片

封面使用现有本地上传目录配置 `app.upload.dir`，在其下新增独立的 `promotion-projects` 子目录，对外访问路径使用 `/uploads/promotion-projects/**`。

- 只允许 JPG、PNG 和 WebP。
- 单个文件最大 2 MB。
- 后端校验文件实际可解码，不能只信任文件名或请求声明的 MIME 类型。
- 文件名由后端生成，不使用客户端原始文件名作为存储路径。
- 新增数据库写入失败时删除本次新上传文件。
- 替换封面时，数据库事务提交后删除旧封面；事务失败时删除新封面并保留旧封面。
- 删除项目时，数据库事务提交后删除该项目的封面文件。

## 7. 管理端页面

后台新增“项目管理”页面，提供：

- 项目分页列表。
- 新增项目表单。
- 编辑项目表单。
- 封面图片选择、预览和替换。
- 启用或停用状态选择。
- 显示顺序输入。
- 删除确认。

页面不提供报白、发布、归档或项目专属业务操作。

## 8. 用户端接口与卡片

```http
GET /api/user/promotion/projects
```

接口只返回 `ENABLED` 项目，并按 `sort_order ASC, id ASC` 排序：

```json
[
  {
    "id": 2,
    "name": "TikTok 短剧推广",
    "coverImageUrl": "/uploads/promotion-projects/example.webp",
    "projectDocumentUrl": "https://example.com/project-document",
    "sortOrder": 20
  }
]
```

用户工作台使用 TanStack Query 请求项目列表，替换当前页面内的静态项目数组。

- 每条项目数据渲染为一张卡片。
- 卡片使用 `coverImageUrl` 展示后台上传的封面。
- 卡片保留“项目文档”按钮，点击后以新标签页打开 `projectDocumentUrl`，并设置 `noopener noreferrer`。
- 用户端不显示已停用或已删除项目。
- 项目列表提供加载、失败重试和空数据状态。
- 桌面端和 320px 以上移动视口均不得发生按钮遮挡或卡片裁切。

## 9. 分层与错误处理

后端沿用现有 `promotion/controller`、`dto`、`entity`、`mapper`、`service`、`vo` 分层：

- Controller 负责管理员或用户身份边界、请求参数校验和响应包装。
- Service 负责 CRUD、启用过滤、排序规则和封面文件生命周期。
- Mapper 只负责 `promotion_project` 表的 SQL。
- 用户端接口不接收项目筛选、状态或排序参数，不能读取停用项目。

前端所有请求继续经过各自现有的共享 HTTP 客户端，并保持当前会话失效和错误提示行为。

## 10. 验证

后端验证覆盖：

- 项目新增、分页列表、详情、修改和物理删除。
- 新增后用户接口可读取启用项目。
- 修改后用户接口返回最新名称、封面、文档 URL 和顺序。
- 停用或删除后用户接口不再返回项目。
- `sort_order ASC, id ASC` 排序稳定。
- 非 HTTPS 文档 URL、非法状态、负数排序和非法图片被拒绝。
- 新增失败、替换封面和删除项目时的文件清理符合事务结果。

管理端验证覆盖：

- 列表、新增、编辑、启停、排序和删除操作正确调用接口。
- 新增必须选择封面，编辑未选择新封面时保留原图。
- 删除前需要用户确认，接口失败时保留当前列表状态并提示错误。

用户端验证覆盖：

- 接口返回一条项目时渲染一张对应卡片。
- 项目文档按钮在新标签页打开配置的 URL。
- 加载、失败重试和空数据状态正确。
- 桌面端和 320px 以上移动视口没有按钮遮挡或卡片裁切。

## 11. 实施顺序

1. 新增项目表、Flyway 迁移和开发重建脚本结构。
2. 实现后端项目 CRUD 和封面文件生命周期。
3. 实现用户端启用项目列表接口。
4. 实现管理端项目管理页面。
5. 用户工作台从静态项目数组切换为接口数据。

本设计只定义项目 CRUD、封面上传和用户端卡片读取。实施前不新增报白、CapCut 归属或其他项目业务。
