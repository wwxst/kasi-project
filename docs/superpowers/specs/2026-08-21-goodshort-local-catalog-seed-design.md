# GoodShort 本地目录假数据设计

日期：2026-08-21

状态：已实施并验证（2026-08-21）

实施结果：可复用的仓库 seed 仅用于本地开发，位于 Flyway 与应用运行时之外；H2 已按仓库原始脚本完成精确执行测试，并覆盖守卫拒绝与幂等。实际 MySQL 8.0.44 首次执行暴露了 error 1137，仓库脚本随后改为分别使用短剧序号与剧集序号临时表，并重新验证了 MySQL 临时表语法模式。按用户明确指示，当前本地 MySQL 数据通过直接导入写入既有且无凭据的 `GoodShort` 连接，未更改其名称、启用状态、币种、报备模式或连接配置；两次显式事务核验均确认 24 部短剧、204 条剧集内容、4 个成功检查点，且内部 ID 保持稳定。由于该既有连接名称并非受保护 seed 要求的精确 fixture 名称，完整守卫 seed 脚本会正确拒绝该连接，因此不声称它已在该非精确连接上端到端执行成功。

## 1. 目标

为当前开发阶段的 GoodShort 短剧目录联调准备一批可重复生成的本地假数据，使管理员目录 API 和管理端表格页可以在尚未取得真实 PID、KEY 前完成分页、筛选、详情、上下架和同步状态展示测试。

假数据只写入开发人员当前的本地 MySQL，不进入生产初始化流程。

## 2. 范围

### 2.1 本次交付

- 新增一个可重复执行的 GoodShort 本地目录 SQL 脚本。
- 创建或复用一个禁用、无凭据的 GoodShort 本地假数据连接。
- 生成短剧、剧集和同步检查点数据。
- 安全预检后，按用户明确指示将目录数据直接导入既有且无凭据的 GoodShort 连接并核对结果；可复用脚本继续保留严格连接守卫。
- 增加聚焦自动化测试，验证脚本可重复执行且关联数据正确。
- 在 `README.md` 和 `AGENTS.md` 记录脚本用途、执行方式和安全边界。

### 2.2 不在本次范围

- 不申请、生成或提交真实 GoodShort PID、KEY。
- 不调用 GoodShort 远端接口。
- 不修改正式 Flyway 迁移或生产建库数据。
- 不增加应用启动时的自动造数器。
- 不增加前端 Mock 模式。
- 不将假数据用于生产、预发布或共享测试环境。

## 3. 文件与执行边界

脚本路径为：

```text
scripts/dev/seed_goodshort_drama_catalog.sql
```

脚本仅由开发人员手动执行，不由 Flyway、Spring Boot Profile、定时任务或应用启动流程自动加载。文件头必须明确标注“仅限本地开发测试，禁止生产执行”。

原计划是在精确匹配的 fixture 连接上完整执行一次受守卫保护的 seed 脚本并通过查询核对结果。实际安全预检发现的是一个不精确匹配但无凭据的既有 GoodShort 连接；用户随后明确指示直接导入目录数据，因此完整守卫 seed 未在该连接上端到端执行。精确脚本已在 H2 上验证；实际 MySQL 已验证临时表语法模式、直接导入、查询计数与幂等性。

## 4. GoodShort 连接保护

脚本先读取 `short_drama_provider.provider_code = 'GOODSHORT'` 的平台记录，再处理平台连接。

- 没有 GoodShort 连接时，创建名为 `GoodShort 本地假数据` 的连接。
- 假数据连接使用 `USD`、`MANUAL` 和禁用状态。
- `partner_id`、`api_key_ciphertext` 和 `base_url` 均保持为空。
- 已存在同名且无凭据的假数据连接时，复用该连接。
- 发现 GoodShort 已存在其他连接、真实 PID、密钥密文或接口地址时，脚本立即失败。
- 脚本不得覆盖、清空、禁用或向真实连接写入假目录。

上述保护即使在本地开发环境也保留，避免开发人员后续配置真实凭据后误执行脚本。

## 5. ID 契约

所有内部主键继续使用当前数据库契约：

- `short_drama_connection.id`
- `provider_drama.id`
- `provider_drama_content.id`
- `provider_sync_checkpoint.id`

这些字段均由数据库 `AUTO_INCREMENT` 生成，脚本不得指定固定主键。

当前 GoodShort 适配器将远端 `bookId` 保存为 `provider_drama.external_drama_id`，将远端 `episodeId` 保存为 `provider_drama_content.external_content_id`。应用本身不会生成这两个平台 ID，因此假数据按相同映射契约提供稳定的数字字符串：

```text
短剧外部 ID：99000001、99000002、...
剧集外部 ID：99000001001、99000001002、...
```

固定的外部 ID 只用于幂等定位和模拟 GoodShort 返回值，不作为本地表主键。

## 6. 假数据组成

脚本生成 24 部短剧，以覆盖默认分页后的多页展示。数据包含：

- `ENGLISH`、`SPANISH` 等语言。
- 多种短剧题材、标题、原始标题和简介。
- `DRAFT`、`PUBLISHED`、`OFFLINE` 三种本地状态。
- 多种远端上下架原始状态。
- 不同远端更新时间和最近发现时间。
- 稳定占位封面，以及少量空封面记录用于验证前端兜底。

每部短剧生成 5 至 12 集，覆盖：

- 连续且从 1 开始的剧集序号。
- 免费与付费剧集。
- 不同标题、片长和远端更新时间。

脚本同时生成全量与增量同步检查点，覆盖成功完成的同步状态，并提供最近成功时间、请求时间、完成时间、抓取数、新增数、更新数和跳过数，供同步状态界面展示。

## 7. 幂等与事务

脚本在事务中执行。短剧按 `(connection_id, external_drama_id)` 定位，剧集按 `(drama_id, sequence_no)` 定位，同步检查点按 `(connection_id, sync_type, language)` 定位。

首次执行插入数据；再次执行更新同一批假数据，不产生重复短剧、剧集或检查点。脚本不得删除不属于本批外部 ID 范围的目录数据，也不得修改其他平台的数据。

执行前置条件、连接保护或任意写入发生错误时，事务整体回滚，避免留下部分生成的数据。

## 8. 清理边界

假数据通过以下组合识别：

- 连接名称为 `GoodShort 本地假数据`。
- 短剧外部 ID 位于本设计保留的 `99000001` 至 `99000024` 范围。

清理时应先删除这些短剧对应的剧集，再删除短剧和该连接下的假同步检查点；只有确认该连接没有其他业务数据或报备关联时，才可删除假数据连接。不得按平台代码批量清空全部 GoodShort 数据。

## 9. 测试与验收

聚焦自动化测试至少验证：

- 脚本可以在已执行正式迁移的测试数据库上运行。
- 内部主键由数据库生成且不依赖固定值。
- 24 部短剧及其剧集、同步检查点均写入正确连接。
- 本地状态、语言、免费/付费剧集和空封面等覆盖场景存在。
- 连续执行脚本两次后记录数量不增加，关联关系不变。
- 存在真实 GoodShort 连接或凭据时脚本拒绝执行且不修改原数据。

本地 MySQL 验收至少核对：

- 假数据连接处于禁用状态且不包含 PID、KEY 密文和接口地址。
- 短剧数量为 24。
- 剧集数量符合每部 5 至 12 集的设计。
- 全量和增量检查点存在。
- 后端管理员目录接口能够分页查询和读取详情。
