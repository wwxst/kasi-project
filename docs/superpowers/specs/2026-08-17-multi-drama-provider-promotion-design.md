# 多短剧平台推广业务设计规格

日期：2026-08-17

## 1. 文档定位

本文定义 Kasi 推广平台后续接入 GoodShort 及其他短剧平台时的统一业务模型、平台适配边界、推广流程、订单同步、转化统计和预计佣金计算规则。

本文描述的是规划架构，尚未实现。当前仓库仍只有管理员与推广用户认证、管理员管理和推广用户管理模块。后续实现必须拆分为独立阶段，不在一次变更中同时交付全部模块。

设计输入为 GoodShort KOC 推广接口文档 v1.0.5。GoodShort 当前提供短剧全量/增量同步、免费内容、媒体账号报备、推广口令和链接、订单列表及订单转化明细接口，但不提供订单实时回调，也不提供 TikTok 锚点接口。

## 2. 目标与非目标

### 2.1 目标

- 一个推广用户可以绑定多个 TikTok、YouTube、Facebook、Instagram 等媒体账号。
- 同一个真实媒体账号同一时间只能属于一个推广用户，且不支持账号转让。
- 同一媒体账号可以分别向多个短剧平台报备，各平台审核状态互不影响。
- 推广用户可以浏览任意已上架、已配置有效分佣规则的短剧。
- 推广用户可以选择观看、单集下载或批量下载免费内容，也可以不使用素材直接生成推广链接。
- 同一媒体账号可以针对同一部短剧生成多条推广链接，以区分不同视频或投放活动。
- 平台按统一模型同步订单和转化数据，并将订单准确归因到推广链接、媒体账号和推广用户。
- 每个平台短剧可以配置独立、带生效时间的预计佣金规则；同一平台短剧在同一时段对所有推广用户使用相同比例。
- 管理员可以导出已支付和已退款订单，由线下人员完成最终核算与打款。
- 后续增加短剧平台时，只新增平台适配实现，不复制整套推广业务。

### 2.2 本期明确不建设

- 在线钱包、余额账户、提现、付款、结算批次和已结算状态。
- 媒体账号转让。
- 单个推广用户的特殊分佣比例。
- GoodShort 的 TikTok 锚点功能；GoodShort 文档没有对应接口。
- 多机构、多租户和机构内部团队权限。
- 同一短剧平台多套机构账号的管理界面和自动分流。数据层保留接入账号边界，但首期每个平台只启用一套账号。
- 自动认定跨平台同名短剧为同一版权内容。首期以“平台短剧”为独立业务对象。

## 3. 方案选择

### 3.1 采用：统一领域模型加平台适配器

核心业务只认识平台、接入账号、平台短剧、媒体账号、平台报备、推广链接、订单、转化数据和分佣规则。GoodShort 的 `pid`、`bookId`、`customParams`、`code` 等字段只存在于 GoodShort 适配层和外部标识字段中。

优点是后续接入新平台时，用户、账号归属、链接归因、佣金和导出逻辑可以复用。平台差异通过能力声明和适配接口隔离。

### 3.2 不采用：每个平台独立建设整套业务表

该方案首个平台上线较快，但会重复建设媒体账号、短剧、推广链接、订单和佣金逻辑，跨平台查询和统一导出也会持续增加分支判断。

### 3.3 不采用：首期建设完整多租户和分账平台

当前没有多机构、团队层级、在线钱包和自动打款需求。提前引入这些能力会扩大权限、账务和数据隔离范围，不符合当前业务边界。

## 4. 总体业务关系

```text
推广用户
  └─ 多个媒体账号
       └─ 在多个短剧平台分别报备
            └─ 选择平台已上架短剧
                 └─ 生成多条推广链接
                      ├─ 同步订单并计算预计佣金
                      └─ 同步每日转化数据
```

核心归因链固定为：

```text
第三方订单
→ 平台接入账号
→ 推广链接追踪号
→ 平台短剧
→ 媒体账号
→ 推广用户
```

数据库内部关联始终使用自增主键。推广用户的 `user_no` 用于展示和搜索，不作为表关联键或外部平台安全凭据。

## 5. 平台与接入账号

### 5.1 短剧平台

短剧平台表示 GoodShort 或未来的平台 B、平台 C。平台记录保存平台编码、名称、启用状态和适配器类型，不保存具体短剧或用户数据。

平台适配器声明自己支持的能力：

- 短剧全量同步
- 短剧增量同步
- 免费内容预览
- 单集下载
- 批量下载
- 媒体账号报备
- 报备状态查询
- 推广链接
- 推广口令
- TikTok 锚点
- 订单同步
- 转化数据同步

前端只展示当前平台实际支持并由管理员启用的能力。GoodShort 不声明 TikTok 锚点能力，因此不显示“创建锚点”。

### 5.2 平台接入账号

接入账号表示一套机构对接凭据，例如 GoodShort 的 `pid + key`。首期每个平台只允许一套启用账号，但所有平台业务记录均保留 `connection_id`，避免未来增加第二套账号时重构短剧、报备、链接和订单关系。

推广用户不查看、不选择接入账号。平台短剧绑定接入账号，系统生成链接和同步数据时自动选择正确凭据。

`key` 不允许明文返回前端、写入日志或进入导出文件。实现时优先使用密钥管理服务或加密存储；数据库只保存密文或密钥引用。密钥读取失败时平台调用安全失败，不允许使用空密钥继续请求。

## 6. 媒体账号与平台报备

### 6.1 媒体账号

推广用户可以绑定多个媒体账号。媒体账号至少包含媒体平台、外部账号 ID、账号名称和主页链接。

核心规则：

- `(media_type, external_account_id)` 全局唯一。
- `user_id` 创建后不可修改，不提供账号转让。
- 报备未通过前，用户可以修正填错的账号 ID、名称和主页链接并重新提交。
- 任一平台已加白后，媒体平台和账号 ID 不可修改；需要使用其他账号时新增媒体账号。
- 用户可以停用账号，但不物理删除；历史链接、订单和转化数据继续保留。
- 已停用账号不能生成新推广链接。

### 6.2 平台报备

同一媒体账号在不同短剧平台分别保存报备记录。绑定账号后，系统立即向用户选定的短剧平台提交报备并定时查询状态。面向业务统一为三种状态：

- `PENDING`：审核中
- `APPROVED`：已加白
- `FAILED`：已失败

只有当前接入账号下状态为 `APPROVED` 的媒体账号，才可以生成该平台的推广链接。

第三方暂时不可用、超时或限流时保持 `PENDING`，由同步任务记录错误并自动重试，不额外暴露技术状态。平台明确拒绝、账号失效或达到既定重试上限后进入 `FAILED`；用户修正资料并重新提交时回到 `PENDING`。

GoodShort 报备映射：

| 统一字段 | GoodShort 字段 |
|---|---|
| 报备类型 | `type=ACCOUNT` |
| 媒体平台 | `media` |
| 外部账号 ID | `accountId` |
| 账号名称 | `accountName` |
| 主页链接 | `accountLink` |

GoodShort 查询状态 `0/1/2` 分别映射为 `PENDING/APPROVED/FAILED`。

## 7. 平台短剧与免费内容

### 7.1 短剧同步

平台短剧按接入账号和外部短剧 ID 唯一。GoodShort 首次使用 `initBooks` 分语言、分页全量同步，之后使用 `incrementBooks` 按更新时间增量同步。

推广用户可见条件必须同时满足：

- 第三方 `showStatus` 有效。
- 本地管理员已上架。
- 所属平台和接入账号已启用。
- 当前时间存在一条有效分佣规则。

第三方下架短剧后，本地停止生成新推广链接，但不删除历史链接、订单、素材记录和统计数据。

### 7.2 短剧详情与素材

短剧详情展示封面、名称、中文名、简介、语言、标签、类型和免费剧集列表。推广用户可以：

- 直接生成推广链接。
- 播放任意免费剧集。
- 下载单集。
- 批量下载全部免费剧集。

观看和下载均不是生成推广链接的前置条件。

GoodShort `freeContent` 返回的是视频链接，示例为 HLS `m3u8`。系统不提前镜像全部内容；播放时按需获取或使用短时缓存。下载时创建异步任务，将允许下载的 HLS 内容封装为普通视频文件，批量下载生成临时压缩包。临时文件到期自动清理。

素材下载能力必须同时满足平台适配器支持、管理员启用和商务合同允许。接口可访问不自动等同于获得二次下载与传播授权。

## 8. 推广链接与活动归因

### 8.1 生成流程

推广用户生成链接时选择平台短剧、本人已加白的媒体账号，并可填写推广名称。推广名称选填；未填写时系统按“平台-短剧-媒体-日期-序号”生成默认名称。

生成前依次校验：

- 推广用户状态正常。
- 媒体账号属于当前用户且未停用。
- 媒体账号在当前接入账号下已加白。
- 平台短剧当前可见且已上架。
- 当前时间存在有效分佣规则。
- 平台支持推广链接或口令能力。

每次生成都创建新的推广记录和唯一 `tracking_no`。同一用户、账号和短剧允许生成多条链接，以分别统计不同视频和活动。

### 8.2 GoodShort 映射

调用 GoodShort 时：

- `bookId` 使用平台短剧的外部 ID。
- `customParams` 使用本地唯一 `tracking_no`，长度不超过 64。
- `codeMedia` 根据媒体账号平台转换。
- `shareUrlType` 根据用户选择的落地页或 OneLink 类型转换。

成功后保存 GoodShort 返回的 `code`、`shareUrl` 和原样返回的 `customParams`。重试生成请求时复用同一个 `tracking_no`，不为一次用户操作创建多条本地推广记录。

## 9. 分佣规则与预计佣金

### 9.1 规则作用域

规则绑定“平台接入账号 + 平台短剧 + 生效时间”。不同短剧可以使用不同规则；同一短剧在同一有效时段对所有推广用户使用相同比例。

同一平台短剧的有效规则时间段不得重叠。没有当前有效规则时，不允许生成新推广链接。订单支付时间无法匹配规则时，保存订单但标记佣金计算异常，禁止猜测或回退到最新规则。

### 9.2 配置字段

后台统一使用百分比 `%` 输入，允许小数：

- 渠道费率，默认 `0%`
- 甲方手续费率，默认 `0%`
- 甲方给我方的分佣比例
- 我方手续费率，默认 `0%`
- 我方给下游的分佣比例

例如千分之三填写为 `0.3%`。数据库统一保存为 `0..1` 的高精度小数，禁止使用 `float` 或 `double`。

### 9.3 公式与精度

```text
推广用户预计佣金
= 充值金额
× (1 - 渠道费率)
× (1 - 甲方手续费率)
× 甲方给我方的分佣比例
× (1 - 我方手续费率)
× 我方给下游的分佣比例
```

示例：充值 100 美元，渠道费 30%，甲方手续费 0%，甲方给我方 80%，我方手续费 0%，我方给下游 70%：

```text
100 × 70% × 100% × 80% × 100% × 70% = 39.20 美元
```

Java 使用 `BigDecimal` 完成计算，中间结果保留高精度，最终推广用户预计佣金按订单币种最小单位保留两位小数并使用 `HALF_UP` 四舍五入。

每笔订单保存五项费率快照、匹配的规则 ID、订单原金额和最终预计佣金。规则修改只影响新支付订单，不重新计算历史订单。

## 10. 订单同步与状态

### 10.1 同步方式

GoodShort 没有订单回调，只能轮询：

- 默认每 5 分钟拉取当天订单。
- 每天早上 8 点后重拉最近 7 个自然日，以发现延迟支付和退款。
- 每周重拉最近 90 个自然日；按自然日切片执行，避免单次查询范围和分页过大。
- 管理员可以按日期手动补拉。
- 频率与 7 日、90 日复核窗口均做成接入账号配置，以上数值为首期默认值；正式启用高频轮询前需与平台确认允许频率和数据时效。

同步任务使用分布式锁或数据库租约，避免多实例重复执行。分页必须完整拉取；单页失败时记录检查点和失败原因，后续从未完成页继续或重新执行整个幂等窗口。

### 10.2 幂等与更新

订单按 `(connection_id, external_order_id)` 唯一。重复拉取时更新原记录，不重复插入，也不重复计算佣金。

GoodShort `customParams` 映射本地 `tracking_no`。无法匹配推广链接的订单保存为“待归因”，管理员可查看异常，但不得自动归属到某个推广用户。

GoodShort 状态映射：

- `0`：`UNPAID`，未支付，预计佣金为零。
- `1`：`PAID`，已支付，按支付时间匹配规则并计算预计佣金。
- `3`：`REFUNDED`，已退款，预计佣金为零。

GoodShort 当前只返回整笔退款状态，没有部分退款金额，因此退款统一按整笔订单处理。订单保留原充值金额和退款状态，导出时不增加额外“应扣回”账务模型。

未知第三方状态保存原始状态码并标记异常，不参与佣金计算。

### 10.3 金额与币种

GoodShort `payMoney` 以最小货币单位返回，但文档未明确所有接入账号的币种。接入账号必须配置 ISO 4217 币种，订单保存原始最小单位金额、币种和格式化金额。不同币种不自动合并，不在本期进行汇率换算。

## 11. 转化数据

GoodShort `analyticalReport` 建议每天早上 8 点后拉取前一天数据。系统按推广链接和自然日保存：

- 点击数
- 归因用户数
- 新注册人数
- 新充值人数
- 新开会员人数
- 充值用户数
- 订单数
- 充值金额

推广用户只能查看本人链接数据，可以按日期、短剧、媒体账号和推广名称筛选。管理员可以查看全部数据。页面必须显示数据日期和最后同步时间，不将每日数据描述为实时统计。

转化报表中的订单数和金额用于运营分析；预计佣金以订单明细和订单费率快照为唯一计算来源，不直接使用汇总报表重复计算。

## 12. 订单导出

管理员可以按平台、接入账号、支付日期、推广用户编号、媒体账号、短剧和订单状态筛选并导出 Excel。推广用户不能导出全平台结算订单，只能查看自己的订单和预计佣金。

默认导出已支付和已退款订单，未支付订单不进入线下核算表。导出至少包含：

- 平台与接入账号名称
- 第三方订单号
- 支付时间
- 订单状态
- 原始金额、币种
- 推广用户编号、昵称和联系方式
- 媒体平台、账号 ID 和账号名称
- 平台短剧 ID、短剧名称
- 推广名称、追踪号、口令和渠道号
- 五项费率快照
- 推广用户预计佣金
- 第三方更新时间和本地同步时间

导出是即时查询，不创建结算批次，不修改订单状态，不记录已结算标记，也不触发付款。

## 13. 概念数据模型

| 表 | 主要职责 | 关键约束 |
|---|---|---|
| `short_drama_provider` | 短剧平台 | `provider_code` 唯一 |
| `short_drama_connection` | 平台机构接入账号 | 首期每个平台仅一条启用记录 |
| `promotion_media_account` | 推广用户绑定的媒体账号 | `(media_type, external_account_id)` 唯一，归属不可转移 |
| `provider_media_filing` | 媒体账号在接入账号下的报备状态 | `(connection_id, media_account_id)` 唯一 |
| `provider_drama` | 平台短剧目录 | `(connection_id, external_drama_id)` 唯一 |
| `provider_drama_content` | 免费剧集元数据 | `(provider_drama_id, sequence_no)` 唯一 |
| `drama_commission_rule` | 平台短剧分佣规则版本 | 同一短剧有效时间段不得重叠 |
| `promotion_link` | 每次生成的推广链接或口令 | `tracking_no` 唯一 |
| `promotion_order` | 第三方订单、费率快照和预计佣金 | `(connection_id, external_order_id)` 唯一 |
| `promotion_daily_metric` | 每条推广链接每日转化统计 | `(promotion_link_id, report_date)` 唯一 |
| `provider_sync_checkpoint` | 同步窗口、游标、状态和错误 | 按连接和任务类型维护 |
| `material_download_task` | 单集或批量素材下载任务 | 文件过期后保留任务结果，不保留临时文件 |

所有业务表使用内部自增 `id` 关联。外部 ID、追踪号、用户编号和平台口令只承担业务展示或外部映射职责。

## 14. 后端模块边界

规划模块仍位于 `com.kasi.backend` 下：

```text
provider/   平台定义、接入账号、能力声明、客户端接口与各平台适配器
drama/      平台短剧、免费内容、上架和分佣规则
promotion/  媒体账号、平台报备、推广链接和素材下载任务
order/      订单同步、归因、状态转换、预计佣金和管理员导出
analytics/  每日转化数据同步与查询
```

每个业务模块继续遵循 Controller、Service 接口、`impl` 实现、Mapper、Entity、DTO 和 VO 分层。平台 HTTP 客户端不放入 Controller 或 Mapper；签名、字段转换和第三方错误映射由对应平台适配器负责。

建议的平台客户端契约按能力拆分，避免一个包含所有平台功能的超大接口。仅实现平台实际支持的能力，调用方先检查能力声明。

## 15. GoodShort 对接要求

### 15.1 签名

- 请求参数中的非空值按参数名 ASCII 升序排列。
- 使用 `key=value` 和 `&` 拼接，再追加机构密钥。
- 对拼接结果计算 MD5 并转为大写，签名放在 `sign` 请求头。
- `timestamp` 由服务端生成毫秒时间戳。
- `sign` 不参与签名，空值不参与签名，参数名区分大小写。
- 密钥、签名前原文和完整认证参数不得写入日志。

签名实现必须使用官方示例构造固定向量测试，防止参数排序、空值和大小写处理发生偏差。

### 15.2 调用可靠性

- 设置连接、读取和整体请求超时。
- 查询类接口可以按退避策略重试。
- 生成链接使用本地请求状态和固定 `tracking_no` 保证重试幂等。
- 第三方限流转换为可识别错误并延迟重试，不在同一请求内无限循环。
- 第三方不可用时保留本地任务和错误原因，不伪造短剧、订单或审核结果。
- 下载远程内容时只允许适配器返回的受信任 HTTPS 地址，并限制文件大小、时长、并发和临时目录，防止 SSRF 与磁盘耗尽。

## 16. 权限边界

### 16.1 推广用户

推广用户只能：

- 管理自己的媒体账号。
- 查看自己的报备状态。
- 浏览可推广短剧和允许使用的免费内容。
- 使用自己的已加白账号生成推广链接。
- 查看自己的推广链接、订单、预计佣金和转化数据。

所有用户接口从认证上下文取得内部用户 ID，不接受请求体传入任意 `userId` 作为归属依据。

### 16.2 管理员

管理员负责平台配置、同步监控、短剧上下架、分佣规则、报备查询、全量订单与转化查询和订单导出。首期沿用当前简单权限模型，不新增 RBAC：

- 只有 `ROLE_SUPER_ADMIN` 可以创建或修改平台接入账号、写入或轮换密钥、启停平台、创建或修改分佣规则。
- `ROLE_ADMIN` 可以查看平台和同步状态、管理短剧本地上下架、查看或重新提交报备、手动补拉数据、查看全部订单与转化数据并导出订单。
- 所有平台配置变更、分佣规则变更、手动同步和全量订单导出必须记录管理员、时间、对象和结果；日志不得包含平台密钥。
- 后续若需要独立财务人员权限，再单独设计 RBAC；本期不以“财务人员”名义新增角色。

## 17. 错误处理与可观测性

- 第三方业务失败、网络失败、限流、签名失败和响应解析失败必须区分记录。
- 用户接口返回稳定的本地错误码，不透传第三方堆栈、密钥或内部 URL。
- 同步任务记录开始时间、结束时间、查询窗口、页数、读取数、新增数、更新数、异常数和最后错误。
- 订单无法归因、订单无法匹配分佣规则、未知状态和币种缺失进入管理员异常列表。
- 页面展示平台数据最后同步时间，避免将轮询数据误认为实时数据。

## 18. 测试设计

### 18.1 平台适配器

- GoodShort 签名固定向量、空值排除、ASCII 排序和大小写测试。
- 每个接口的请求映射、分页、成功响应、第三方业务错误、超时、限流和畸形响应测试。
- 能力声明测试，确保 GoodShort 不暴露锚点功能。

### 18.2 媒体账号与报备

- 一个用户绑定多个账号。
- 同一媒体账号不能被不同用户重复绑定。
- 归属用户不可修改。
- 审核中或已失败时允许修正错误资料并重新提交，已加白后账号 ID 不可修改。
- 不同平台报备状态互不影响，只有当前平台已加白才能生成链接。

### 18.3 短剧、链接与素材

- 全量和增量同步幂等、上下架状态正确。
- 无有效分佣规则时短剧不可推广。
- 同一账号和短剧可以生成多条不同追踪号的链接。
- 用户不能使用其他用户的媒体账号。
- 播放、单集下载、批量下载、过期清理和下载限制测试。

### 18.4 订单、佣金与报表

- 重复同步同一订单不重复插入。
- 未支付转已支付、已支付转已退款正确更新。
- 无法归因、未知状态和缺少规则不产生佣金。
- 百分比小数、千分级费率、零手续费和最终 `HALF_UP` 两位小数测试。
- 规则版本按支付时间匹配，历史订单费率快照不随规则修改变化。
- 转化数据按链接和日期幂等更新，不用于重复计算佣金。
- 推广用户只能查询本人数据；管理员导出包含已支付和已退款，不包含未支付。

### 18.5 调度与故障

- 多实例调度只有一个执行者。
- 分页中途失败可恢复且不丢失、不重复业务数据。
- 第三方不可用时本地已有数据不被清空。
- 密钥、签名原文和敏感认证参数不出现在日志、响应或导出文件。

## 19. 建议实施拆分

该设计包含多个独立子系统，实施时按以下顺序逐个编写计划和验收：

1. 短剧平台接入账号与 GoodShort 通信基础。
2. GoodShort 短剧目录全量/增量同步与后台上下架。
3. 推广用户媒体账号与 GoodShort 报备。
4. 平台短剧分佣规则与可推广条件。
5. 免费内容播放/下载与多推广链接生成。
6. 订单同步、归因、预计佣金和管理员导出。
7. 每日转化数据同步与推广用户数据页面。

每一模块必须独立形成可运行、可测试的增量，包含所需数据库迁移、接口、权限、定向测试、完整回归测试和文档同步。当前模块完成并经用户验收后，才为下一模块编写详细实施计划。未完成的后续模块继续标记为规划，不得写入 README 的“已实现”部分。

## 20. 验收标准

- 新平台接入不复制媒体账号、推广链接、订单、佣金和导出业务。
- 同一媒体账号不能归属多个推广用户，也不能转让。
- GoodShort 未加白账号不能生成 GoodShort 推广链接。
- 同一账号和短剧可以生成多条可独立统计的推广链接。
- 平台短剧没有有效分佣规则时不能推广。
- 订单重复拉取幂等，状态变化更新原记录。
- 预计佣金严格使用订单支付时间对应的费率快照，并按两位小数四舍五入。
- 已退款订单保留原金额，预计佣金为零。
- 推广用户只查看自己的订单和统计；管理员才能导出全量结算订单。
- GoodShort 不显示锚点能力；未来平台只有在适配器声明支持时才显示。
- 当前系统不出现钱包、提现、在线付款和已结算状态。
