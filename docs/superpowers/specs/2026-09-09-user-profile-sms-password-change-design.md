# 用户个人中心手机验证码修改密码设计

## 1. 状态与目标

本文描述已批准但尚未实施的跨前后端认证契约变更。当前实现仍要求推广用户在个人中心提交原密码、新密码和确认密码；实施完成并通过验证后，当前文档才能改写为新行为。

目标是把推广用户个人中心的修改密码流程改为两步：先验证当前账号绑定手机号收到的验证码，验证通过后才显示新密码表单。密码修改成功后，账号全部旧会话失效，当前页面清除本地会话并返回登录页。

## 2. 范围与非目标

本次范围包括：

- `kasi-backend` 的推广用户本人改密 API、验证码场景、短信模板选择和回归测试；
- `kasi-user-web` 的认证 API 类型、个人中心两步改密交互和回归测试；
- 受影响的后端、用户端当前行为文档。

本次不包括：

- 管理员本人或管理员代用户重置密码流程；
- 邮箱验证码；
- 新短信模板配置、数据库字段或 Flyway 迁移；
- 登录页公开的忘记密码流程；
- 个人资料手机号变更的其他安全策略；
- 与本需求无关的页面重构或历史清理。

## 3. 方案决策

采用登录态专用验证码接口和一次性改密凭证，不直接复用接收任意手机号的公开忘记密码接口。

后端始终根据当前认证用户 ID 查询手机号。前端不提交可修改的手机号，因此不能把验证码发送到另一个账号或临时输入的号码。验证码新增独立的 `CHANGE_PASSWORD` 场景，使其 Redis 验证码、冷却、每日计数和失败计数与注册、登录、忘记密码隔离。

`CHANGE_PASSWORD` 在短信配置层复用现有 `reset_password_template_code`。验证码校验成功后复用现有 `PasswordResetTokenService` 签发 10 分钟有效的一次性凭证，不新增另一套临时凭证基础设施。同一推广用户只保留最新密码操作凭证；新签发的改密或找回密码凭证会使该用户先前凭证失效。

## 4. API 契约

三个接口都属于 `/api/user/auth`。前两个接口新增，第三个接口替换推广用户本人改密的现有请求契约。

### 4.1 发送改密验证码

```http
POST /api/user/auth/password/change/code
Authorization: Bearer <access-token>
```

请求无业务字段。后端根据当前用户读取已绑定手机号，以 `CHANGE_PASSWORD` 场景发送验证码。成功响应不返回手机号、验证码、模板信息或供应商请求信息。

当前用户不存在、已不可用或未绑定手机号时不得发送。其中未绑定手机号返回新的用户认证错误码，消息明确提示先绑定手机号。验证码发送频率、每日上限、发送失败和 Redis 不可用继续使用现有错误语义。

### 4.2 校验改密验证码

```http
POST /api/user/auth/password/change/verify
Authorization: Bearer <access-token>
Content-Type: application/json

{
  "code": "123456"
}
```

请求 DTO 只接收非空验证码。后端再次根据当前用户读取绑定手机号，并以 `CHANGE_PASSWORD` 场景原子校验验证码。成功后为当前用户和 `USER` 主体类型签发密码重置凭证：

```json
{
  "resetToken": "<opaque-token>",
  "expiresIn": 600
}
```

验证码错误、过期或失败次数超限时不签发凭证。手机号在发送和校验之间发生变化时，旧手机号收到的验证码不能通过新手机号的校验。

### 4.3 提交新密码

```http
PUT /api/user/auth/password
Authorization: Bearer <access-token>
Content-Type: application/json

{
  "resetToken": "<opaque-token>",
  "newPassword": "new-password",
  "confirmPassword": "new-password"
}
```

推广用户使用独立 DTO，不再提交或校验 `oldPassword`。管理员继续使用其现有 DTO 和流程。

后端原子预占凭证后必须同时确认：主体类型为 `USER`，且凭证用户 ID 等于当前认证用户 ID。任一条件不满足均返回重置凭证无效，不修改任何账号密码。新密码仍需满足现有长度和 UTF-8 字节限制、两次密码一致，且不能与当前密码相同。

密码更新与会话版本变更处于同一事务语义中。事务提交后消费凭证并使该账号全部旧 Token 失效；事务回滚时按现有 `PasswordResetTokenService` 语义把预占凭证恢复为可用状态。

## 5. 后端组件变化

- `VerificationScene` 增加 `CHANGE_PASSWORD`。
- `SmsConfigServiceImpl.requireRuntimeConfig` 将 `CHANGE_PASSWORD` 映射到 `resetPasswordTemplateCode`。
- 新增仅含 `code` 的改密验证码校验 DTO。
- 新增推广用户专用改密 DTO，字段为 `resetToken`、`newPassword`、`confirmPassword`。
- `UserAuthController` 增加两个登录态验证码端点，并把当前用户 ID 传给服务。
- `UserAuthService` 和 `UserAuthServiceImpl` 增加发送、校验方法，并把本人改密从原密码校验改为当前用户绑定的一次性凭证校验。
- `ErrorCode` 增加“当前账号未绑定手机号”的用户认证错误，避免复用语义不符的参数或账号错误。
- 现有验证码哈希存储、60 秒冷却、每日 10 次上限、5 分钟有效期、连续失败限制和短信发送失败回收逻辑保持不变。

不新增 Controller、Manager、Parser 或新的 Token 服务层。

## 6. 前端交互

个人中心“安全设置”保留在现有页面内，使用组件局部状态表示 `VERIFY_MOBILE` 和 `SET_PASSWORD` 两步，不新增路由或全局状态。

第一步展示：

- 当前账号的脱敏手机号，例如 `138****8000`；
- 6 位验证码输入框；
- “发送验证码”按钮；
- “验证并继续”主操作。

发送接口成功后才开始 60 秒重发倒计时。验证码校验失败时保留在第一步，允许用户修改验证码或在倒计时结束后重新发送。验证码校验成功后，前端只把 `resetToken` 保存在 `ProfilePage` 组件内存中，并切换到第二步。

第二步只展示新密码、确认新密码和“修改密码”按钮，不再展示当前密码。刷新页面、离开个人中心或组件卸载后，内存凭证自然丢失，用户必须重新验证；凭证不得写入 URL、日志、 Zustand、`localStorage` 或 `sessionStorage`。

当前用户未绑定手机号时，第一步不显示可发送的验证码操作，显示“请先在基本信息绑定手机号”的明确提示。前端只显示后端 `/me` 返回手机号的脱敏形式，发送和校验均不把该手机号作为请求参数。

修改成功后清除 Zustand 会话和 TanStack Query 缓存，提示“密码修改成功，请重新登录”，并以 replace 导航到 `/login`。修改失败时保留第二步；凭证是否仍可重试由后端事务和一次性凭证状态决定，前端不自行伪造成功状态。

## 7. 错误与安全边界

- 所有新端点都要求 `USER` 登录态，不能加入匿名白名单。
- 手机号只从当前数据库记录读取，不能信任前端值或 JWT 内的联系方式。
- 验证码按 `CHANGE_PASSWORD` 场景独立存储并原子消费。
- 改密凭证必须同时匹配 `USER` 主体和当前用户 ID，防止跨账号使用。
- Redis 或短信发送状态不可确认时安全失败，不降级绕过验证码。
- 凭证过期、已消费或已被新凭证替换时统一返回现有重置凭证无效错误。
- 新旧密码相同、确认密码不一致和密码格式不合法继续返回现有业务或校验错误。
- 生产日志不得记录验证码、原始凭证、密码或完整手机号。

## 8. 验证设计

后端自动化测试覆盖：

- 发送接口使用当前用户绑定手机号和 `CHANGE_PASSWORD` 场景；
- 未绑定手机号时拒绝发送；
- 正确验证码返回绑定当前用户的一次性凭证，错误验证码不返回凭证；
- `CHANGE_PASSWORD` 选择现有找回密码短信模板；
- 未经验证码不能提交新密码；
- 其他用户或其他主体的凭证不能修改当前用户密码；
- 新密码与当前密码相同、确认密码不一致时拒绝；
- 成功后密码更新、凭证被消费且旧 Token 失效；
- 失败事务不把凭证永久留在处理中。

前端自动化测试覆盖：

- 初始只显示脱敏手机号和验证码步骤，不显示新密码输入框；
- 发码成功后才启动倒计时；
- 验证失败不进入第二步；
- 验证成功后才显示新密码表单，并只在内存保存凭证；
- 最终请求包含凭证、新密码和确认密码，不包含原密码或手机号；
- 修改成功后清除会话、查询缓存并返回登录页；
- 未绑定手机号时不能发送或验证。

完成前运行：

```powershell
cd kasi-backend
.\mvnw.cmd verify

cd ..\kasi-user-web
pnpm install --frozen-lockfile
pnpm check

cd ..
git diff --check
```

页面需在桌面视口和 320px 宽移动视口进行浏览器检查，确认两步表单、按钮、提示和最长文案没有重叠或裁切。

没有真实阿里云配置时，真实短信送达验收记录为 `SKIP`。自动化测试只能证明发送调用、场景隔离与模板选择，不能把真实短信送达写成 `PASS`。
