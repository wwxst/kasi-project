# 管理端菜单目录整理设计

## 状态

已确认设计，尚未实施。

## 背景

管理端当前将“用户管理”作为独立入口，并把短剧目录、同步、账号报备、推广任务和推广订单拆散在不同层级，无法直接体现短剧推广的业务关系。此次调整只整理管理端菜单目录，不改变页面功能和后端契约。

## 目标

- 按用户管理、管理员管理、短剧管理和系统设置整理管理端导航。
- 将账号报备、推广任务和推广订单归入“短剧管理”。
- 将短剧目录与两类同步入口归入“短剧管理”。
- 将“短剧同步”和“剧集同步”归入“同步管理”二级目录。
- 保留现有路由地址、页面组件、接口、权限判断和移动端抽屉行为。
- 让当前路由所在的菜单分支能够正确展开。

## 菜单结构

```text
用户管理
管理员管理                         （仅超级管理员）

短剧管理
├── 短剧目录
├── 账号报备
├── 推广任务
├── 推广订单
└── 同步管理
    ├── 短剧同步
    └── 剧集同步

系统设置
├── 平台接入
├── 分佣规则
├── 定时任务
└── 系统配置                         （仅超级管理员）
```

“用户管理”和“管理员管理”保持顶级入口，不额外增加“账号管理”父级目录。这样可以减少账号管理场景的点击层级，同时保留管理员权限入口的显著性。

“短剧管理”是唯一的业务父目录。账号报备、推广任务和推广订单直接作为其子项；同步相关页面通过“同步管理”继续分组，避免把两个同步入口与日常运营入口混在同一层。

“系统设置”只承载平台接入、分佣规则、定时任务和系统配置。系统配置页面内部仍维护短信与邮箱配置，菜单显示名称统一为“系统配置”，仅影响显示，不改变路由和页面标题。

## 权限与交互

- 普通管理员不显示“管理员管理”和“系统配置”。
- 普通管理员仍可看到其余菜单，不显示空的权限专属分组。
- 进入 `/drama/catalog`、`/promotion/media-accounts`、`/promotion/links` 或 `/promotion/orders` 时展开“短剧管理”。
- 进入 `/drama/sync/catalog` 或 `/drama/sync/content` 时展开“短剧管理 → 同步管理”。
- 进入 `/system-config/*` 时展开“系统设置”。
- 桌面端折叠侧栏和移动端 Drawer 继续复用同一套菜单项。
- 菜单点击只负责路由跳转；不新增动态菜单、后端菜单接口或新的权限模型。

## 实施范围

预计修改：

- `kasi-admin-web/src/layouts/AdminLayout.tsx`：重排菜单项并补充“同步管理”嵌套目录。
- `kasi-admin-web/src/layouts/AdminLayout.test.tsx` 与 `kasi-admin-web/src/App.test.tsx`：覆盖新层级、当前分支展开和超级管理员/普通管理员可见性。
- `docs/projects/kasi-admin-web.md`：同步当前导航行为。

不修改：

- 后端 Java、数据库迁移和 API。
- React Router 路由地址及页面功能。
- 管理端认证、超级管理员判断和现有移动端菜单容器。
- 用户端菜单及用户端页面。

## 验证

- 管理端 `git diff --check`。
- 测试超级管理员能看到全部可用目录，普通管理员看不到两个超级管理员专属入口。
- 测试短剧目录、推广页面、同步页面和系统设置页面的菜单层级及展开状态。
- 复核只修改菜单、对应测试和导航说明，不引入后端或 schema 变更。

## 非目标

- 不新增工作台、仪表盘或未实现业务菜单。
- 不把用户端导航改成管理端同款结构。
- 不实现动态权限菜单、菜单拖拽排序或菜单配置后台。
- 不改变任何已有业务流程、接口路径或页面数据。
