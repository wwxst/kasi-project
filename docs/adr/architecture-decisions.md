# 架构决策记录规范

本文件定义本仓库如何记录重要架构决策。重要决策不能只存在于聊天、代码注释或某次提交信息中。

## 1. 何时必须记录

满足任一条件就必须新增或更新记录：

- 改变模块边界、依赖方向、事务边界或数据所有权；
- 改变 API、DTO、错误码、权限、会话、配置或数据库契约；
- 引入或移除外部平台、异步任务、缓存、一致性或并发模型；
- 采用破坏性重构、迁移/重建策略或影响运行与发布流程的技术方案；
- 明确拒绝一个会影响后续实现的备选方案。

单纯修复单模块内部实现且不改变上述契约时，可在模块文档和提交说明中记录，不必新增 ADR。

## 2. 记录位置与状态

本文件是索引和规则入口；详细记录可直接追加在本文件，或放在 `docs/adr/ADR-XXXX-<slug>.md` 并在此处建立索引。状态只能使用：

- `提议`：正在讨论，不能作为当前实现依据；
- `已批准`：方案已确认，但尚未全部交付；
- `已实施`：代码、迁移、测试和文档已完成并有验证证据；
- `已废弃`：被新决策替代，必须链接替代记录。

README 和 AGENTS 只能引用 `已实施` 的当前行为；`提议`、`已批准` 和 `已废弃` 必须明确标注状态。

## 3. 必填记录格式

```markdown
# ADR-XXXX: 标题

- 日期：YYYY-MM-DD
- 状态：提议 | 已批准 | 已实施 | 已废弃
- 范围：模块、接口、数据表或运行环境
- 关联：任务、Issue、设计文档、替代或被替代 ADR

## 背景与问题
描述触发决策的事实、约束和根因证据。

## 决策
写出唯一明确的采用方案、边界和不做的事情。

## 备选方案
列出至少一个被拒绝方案及拒绝理由；没有实际备选时说明原因。

## 影响
说明对 API、数据、权限、性能、运维、测试和开发体验的正负影响。

## 迁移与回滚
说明开发库重建、数据升级、发布顺序和失败回滚方式；不需要时写明“不需要”。

## 验证证据
列出测试命令、关键结果、运行环境和文档同步位置。
```

## ADR-0002：GoodShort 订单自动同步复用通用定时任务

- 日期：2026-08-25
- 状态：已实施
- 范围：`promotion`、`scheduledtask`、`system_scheduled_task`、管理端定时任务页
- 关联：`kasi-backend/docs/superpowers/specs/2026-08-25-goodshort-order-scheduled-sync-design.md`、`kasi-backend/src/main/resources/db/kasi_promotion.sql`、[ADR-0003](ADR-0003-database-schema-time-contract.md)

### 背景与问题

GoodShort 订单原先只能由管理员手动调用同步接口，无法稳定形成订单归因和 CPS 佣金数据。仓库已有每分钟扫描 `system_scheduled_task`、数据库租约和定时任务管理页；订单分页、幂等、归因和佣金快照也已有实现。

### 决策

新增固定任务 `GOODSHORT_ORDER_SYNC`，默认每分钟同步最近 3 天。复用现有调度扫描器、任务租约和管理页，不增加第二个 Spring `@Scheduled`、第二张任务表或第二个页面。抽取 `PromotionOrderSyncService`，供自动任务和 `POST /api/admin/promotion/orders/sync` 手动补拉共同使用。自动窗口由调度器的 `Clock` 计算为 `now.minusDays(3)` 到 `now`；历史范围继续由管理员显式传入。

任务有效周期由 `cycle_type=INTERVAL_MINUTES` 和 `interval_value=1` 驱动。旧版兼容字段 `interval_minutes` 仍保存合法值 5，不扩大既有数据库检查约束。

### 备选方案

拒绝新增第二个 Spring `@Scheduled`：会形成重复的周期配置、并发控制和运维入口。拒绝在调度器中复制订单分页代码：会使手动和自动同步的归因、汇总和异常语义分叉。

### 影响

开发空库重建脚本和生产 Flyway 迁移链均包含固定订单同步任务记录，订单同步 Service 由自动任务和管理员手动补拉共用；已有订单归因、幂等、五项费率快照和退款冲销语义不变。自动任务失败仍沿用现有调度器日志和下一轮调度行为；不新增第二套调度器、运行历史、死信、检查点或告警。

### 迁移与回滚

当前开发数据库可按 [ADR-0004](ADR-0004-production-database-migrations.md) 从完整初始化 SQL 删除重建；生产数据库按不可变 Flyway 链独立升级。本 ADR 不改变迁移、备份或失败停止发布规则。

### 验证证据

当前 `SystemScheduledTaskMapper` 持久化测试覆盖到期、单租约持有者和完成后的下一次运行时间；完整验证入口以 [测试规范](../development/testing.md) 为准。旧版 338 个后端测试和 58 个管理端测试仅是当时交付证据，不作为当前健康状态。
