我会严格按你刚才那份 Deep Review 要求拆成独立模块审查。

审查顺序
阶段	模块	核心要确认的事情
0	甲方 API 基准清单	甲方到底一共有多少接口、每个接口契约是什么
1	短剧目录同步	目录、多语言、checkpoint、手动/定时同步、数据库、前端
2	剧集同步	目录完成后任务是否真正被 Worker 消费，剧集是否最终落库
3	媒体账号报白	用户提交 → /filing/report → /filing/query → 状态展示是否完整
4	推广任务	推广任务到底有没有真正的业务模型、接口、页面和消费者
5	推广链接	生成、保存、重复查看、唯一归属、customParams、codeMedia
6	订单转化 analyticalReport	Scheduler → Client → Service → DB → 用户归因
7	用户推广数据	用户是否真的能看到转化、订单、统计
8	管理端推广数据	管理员是否真的能查询真实推广、订单和转化数据
9	项目管理	CAP/CPS/CPM、分佣、API/人工、报白模式等配置有没有真实消费者
10	数据库专项	无消费者表/字段、旧字段、重复状态、历史模型
11	代码与旧链路专项	Fake Integration、旧 Worker、孤儿 Service/DTO/Controller、旧页面
12	最终总验收	汇总覆盖率、闭环率、P0/P1，以及最终修改顺序

每个模块我都只审这个模块，不把其他模块的问题混进来。比如审 推广链接 时，就专门追：

用户端 → Controller → Service → Client → 甲方 API → DB → 查询接口 → 用户端

并且固定给出：

甲方契约 → 当前真实实现 → 真实调用链 → DB读写 → Scheduler/Worker → 前端消费者 → Fake Integration → P0/P1/P2 → 删除候选 → 本模块最终结论。

媒体报白模块：✅ 业务闭环完整
